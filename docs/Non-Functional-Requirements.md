# Campus Connect — Non-Functional Requirements

## 1. Security

The system shall protect user information and restrict access to authorized users based on their roles and permissions.

## 2. Performance

The system should respond to normal user requests within an acceptable amount of time under expected usage.

## 3. Usability

The system should provide a simple, clear, and user-friendly interface that can be easily understood by students, faculty, and administrators.

## 4. Reliability

The system should operate consistently and minimize errors or unexpected failures during normal use.

## 5. Scalability

The system should be designed so that additional users, courses, resources, and features can be supported as the application grows.

## 6. Maintainability

The application should use a well-organized and modular code structure so that future developers can easily maintain and update it.

## 7. Availability

The system should be available to authorized users whenever the application is running and deployed.

## 8. Compatibility

The web application should work correctly on commonly used modern web browsers such as Google Chrome and Microsoft Edge.

## 9. Data Integrity

The system should maintain accurate and consistent user, course, assignment, announcement, and resource data.

## 10. Backup and Recovery

The project should support appropriate database backup and recovery practices to reduce the risk of permanent data loss.
